# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Kee Vault 2 is a Flutter (Android + iOS) password manager. Vaults are stored in KeePass KDBX format, locally on device and optionally synced to the Kee Vault service (compatible with Kee Vault v1). Dart package name is `keevault` (imports are `package:keevault/...`).

## Commands

Flutter version is pinned via FVM in `.fvmrc` (CI reads it from there); use `fvm flutter` if the global SDK differs.

```bash
flutter pub get
flutter analyze                                  # CI runs this; must be clean
flutter test                                     # all unit/widget tests
flutter test test/url_matching_test.dart         # single file
flutter test test/url_matching_test.dart --plain-name 'minimum domain match'   # single test by name
```

Running / building requires `--dart-define`s read by `lib/config/environment_config.dart`:

- `KEEVAULT_STAGE` = `dev` (default) | `beta` | `prod` — selects backend URLs/stage.
- `KEEVAULT_CHANNEL` = `dev` (default) | `sideload` | `play`.
- `IAP_GOOGLE_PLAY` / `IAP_APPLE_APP_STORE` — presence enables in-app purchase for that store.
- iOS also uses `KEEVAULT_NAME_SUFFIX` / `KEEVAULT_ID_SUFFIX` (consumed by `ios/Flutter/*.xcconfig` to make beta/dev bundle IDs).

```bash
flutter run --dart-define KEEVAULT_STAGE=dev --dart-define KEEVAULT_CHANNEL=dev
flutter build appbundle --dart-define KEEVAULT_STAGE=beta --dart-define KEEVAULT_CHANNEL=sideload
flutter build ios --config-only --release --no-codesign --dart-define KEEVAULT_STAGE=prod --dart-define KEEVAULT_NAME_SUFFIX= --dart-define KEEVAULT_ID_SUFFIX= --dart-define IAP_APPLE_APP_STORE=yes
```

`.vscode/launch.json` and `.vscode/tasks.json` hold the canonical variants. Release/fastlane and Patrol screenshot procedures are in `RELEASE.md`; IAP debugging requires the `iap-debug-hack` branch (see `IAP_DEBUG.md`).

## Localisation

Strings live in `lib/l10n/intl_en.arb`; `lib/generated/` (`S.of(context)`) is generated by the Flutter Intl IDE plugin (`flutter_intl` section in `pubspec.yaml`), not by `flutter gen-l10n`. Don't hand-edit `lib/generated/`.

The IDE plugin is a wrapper around the `intl_utils` package, which can be run from the CLI to regenerate after editing the ARB file (run from the repo root; it reads the `flutter_intl` config and uses the default `lib/l10n` → `lib/generated` paths):

```bash
dart pub global activate intl_utils   # one-off, if `dart pub global list` doesn't show it
dart pub global run intl_utils:generate
```

Add new keys to `intl_en.arb` (use `{placeholder}` syntax for parameters, e.g. `"unexpected_error": "... {error}"`), regenerate, then reference them as `S.of(context).keyName`. Commit the regenerated `lib/generated/` files alongside the ARB change. The command needs the Dart SDK to be able to write to its own cache directory, so it fails in a read-only sandbox.

## Dependencies

Many critical dependencies are kee-org forks pulled from git (`kdbx`, `biometric_storage`, `argon2_ffi`, `srp`, `flutter_autofill_service`, etc.). `pubspec.yaml` `dependency_overrides` may point at sibling checkouts (e.g. `../flutter_autofill_service/`) during development — check it before assuming the git ref is what's being built.

## Architecture

**Startup**: `lib/main.dart` initialises settings, Matomo, `PaymentService`, and the public suffix list (`assets/public_suffix_list.dat`, required for URL matching) inside `runZonedGuarded`; the zone error handler shows error dialogs via the global navigator key (with special handling for `KeeLoginFailedMITMException`). `lib/widgets/kee_vault_app.dart` constructs services/repositories, registers all cubits with `MultiBlocProvider`, configures Fluro routes (`lib/config/routes.dart` + `route_handlers.dart`), and listens for Android autofill intents (`receive_intent`) to switch into autofill mode.

**State**: `flutter_bloc` Cubits in `lib/cubit/` (each `x_cubit.dart` has a matching `x_state.dart`). The central one is `VaultCubit` (~1900 lines) which owns the vault lifecycle: startup/unlock, local open, download, refresh/merge with remote, save, upload, quick unlock, free-user ↔ account import, password changes. `AccountCubit` handles sign-in/registration/subscription state via `UserRepository`. `AutofillCubit` detects autofill/save requests and contains URL-matching logic (`AutofillCubit.urlsMatch`, covered by `test/url_matching_test.dart`).

**Vault storage & sync**:
- `LockedVaultFile` (encrypted bytes) → unlocked into `LocalVaultFile` / `RemoteVaultFile` / `DemoVaultFile` (`lib/vault_file.dart`). `VaultFileVersions` tracks current, pending and remote-merge-target versions.
- `LocalVaultRepository` reads/writes KDBX files on device. Remote updates are *staged* locally (`stageUpdate`/`loadStagedUpdate`) and merged with KDBX merge semantics; "free" users (no account) have a separate local file that can be imported into an account vault.
- `RemoteVaultRepository` + `lib/vault_backend/` talk to the Kee Vault service: SRP authentication (`srp.dart`), JWT tokens/claims/feature flags, `StorageService`, `UserService`, `SubscriptionService`. Backend errors are typed in `vault_backend/exceptions.dart`.
- KDF: Argon2 via FFI (`kdbx_argon2_ffi.dart`), with derived-key caching in `kdf_cache.dart`.

**Quick unlock & credentials**: `lib/credentials/quick_unlocker.dart` stores vault credentials in biometric-protected storage so the app (and autofill extension) can reopen without the master password; cached credential hashes expire (`expiring_cached_credential_hash*.dart`).

**Autofill (cross-platform, partly native)**:
- Android: `flutter_autofill_service` plugin plus `android/app/src/main/kotlin/.../AutofillActivity.kt`; the Flutter app itself runs in autofill mode. Kee Vault uses the plugin's in-app selection flow (`AutofillCubit.ensureInAppSelectionPreferences`): Android offers one locked "Autofill with Kee Vault" suggestion, tapping it opens our own entry picker, and every selection (matched or not) is returned with `AutofillService().resultWithDataset` via `AutofillCubit.fillWithEntry`; `cancelFill` declines with `resultWithDatasets(null)`. The legacy `/autofill` unlock launch shows the same picker. Preference setters must use `AutofillPreferences.copyWith` so they don't reset the flow flags.
- Android matching and trust live in `lib/autofill_matching.dart`: `AutofillTarget` assesses the app id and the website as two independent signals (verified/unverified). Only an id with `appIdSource == component` is a verified app (view-node and window-title ids are chosen by the app itself, and a browser's package id is never an app identity). The web signal is only the plugin's `focusedWebDomain`, trusted by its own `dalVerified` (`userSelected` means unverified). Every other domain goes in `otherDomains`, which is display-only and never matched or learned, matching the plugin, which fills only the focused domain's fields. Hosts with no registrable domain (e.g. an opaque-origin `null`) are ignored. Filling asks for confirmation when no signal is verified, or when the chosen entry matched only through an unverified site (`requiresConfirmationFor`). Our own running package (from `PackageInfo`) is always excluded. `AutofillMatches` classifies each entry once per request (tiers, match strength) and `UrlMatcher.classifyUrl` does URL comparison (equality only, never substring). Entries chosen are linked back to whichever signals were verified (`AutofillTarget.associationFor`) via a persistent queue applied to the vault on next save (`VaultCubit.addAutofillPersistentQueueItem` / `applyAndConsumePendingAutofillAssociations`). The picker UI is in `lib/widgets/entry_list.dart`, `autofill_target_card.dart` and `autofill_match_badge.dart`; the save flow (`autofill_save.dart`) uses the same target assessment.
- iOS: a separate native Swift credential provider extension in `ios/KeeVaultAutofill/` using a Swift KDBX implementation in `ios/KdbxSwift/`. It shares the vault via an App Group directory — on iOS `LocalVaultRepository.getStorageDirectory()` asks the native side for this path over the `com.keevault.keevault/autofill` MethodChannel. Changes the extension makes are merged back by `VaultCubit.autofillMerge` / `LocalVaultRepository.tryAutofillMerge`. Changes to vault file layout or credential storage must stay compatible with both sides.

**Payments**: `lib/payment_service.dart` wraps `flutter_inapp_purchase`; only active when the matching `IAP_*` define is set.
